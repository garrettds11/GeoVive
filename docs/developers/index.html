Overview

GeoVivé stores places as features (standard GeoJSON) grouped into datasets. Each dataset has an owner and is either public or private. The API is JSON over HTTPS.

Base URL: https://api.geovive.link

All paths below are under /v1. Public data needs no key; writes need a signed-in user's token.

Authentication

GeoVivé uses Amazon Cognito (OpenID Connect) with Google sign-in. Authenticated calls send the user's access token:

Authorization: Bearer <access_token>
SettingValue
Issuerhttps://cognito-idp.us-east-1.amazonaws.com/us-east-1_cLqbEZJhi
Sign-in domainhttps://auth.geovive.link
FlowAuthorization code + PKCE
TokenAccess token (token_use: access); the user is identified by its sub claim

Tokens are currently issued only to GeoVivé's own web app. Third-party access is coming through connected apps.

Access rules

  • Reads need no token. Public datasets are returned to everyone. Private datasets are returned only to their owner, when a valid token is sent; everyone else gets 404, so a private dataset's existence isn't revealed.
  • Writes (create, update, delete) always need a token, and only the dataset's owner may change it or its features.
  • An invalid or expired token on a read returns 401 rather than being ignored.
  • Browser calls are accepted from GeoVivé's own sites. Server-to-server calls aren't limited by origin.

Datasets

MethodPathAuthDescription
GET/v1/datasetsoptionalPublic datasets, plus your private ones when signed in
POST/v1/datasetsrequiredCreate a dataset (you become the owner). Returns 201
GET/v1/datasets/{datasetId}optionalOne dataset
PATCH/v1/datasets/{datasetId}ownerUpdate name, description or visibility
DELETE/v1/datasets/{datasetId}ownerDelete the dataset and all its features. Returns 204

Create / update body

{
  "name": "Scouting spots",          // required on create
  "description": "Optional text",
  "visibility": "private"            // "private" (default) or "public"
}

Dataset object

{
  "datasetId": "world-capitals",
  "name": "World Capitals",
  "description": "National capitals of the world (Natural Earth)…",
  "visibility": "public",
  "ownerId": "system",
  "source": "https://www.naturalearthdata.com/",
  "featureCount": 215,
  "createdAt": "2026-09-26T01:51:59.386Z",
  "updatedAt": "2026-09-26T01:51:59.386Z"
}

Features

MethodPathAuthDescription
GET/v1/datasets/{datasetId}/featuresoptionalA FeatureCollection. Query: limit (default 500, max 1000), nextToken
POST/v1/datasets/{datasetId}/featuresownerAdd a feature. GeoVivé assigns the ID. Returns 201
GET/v1/datasets/{datasetId}/features/{featureId}optionalOne feature
PUT/v1/datasets/{datasetId}/features/{featureId}ownerReplace a feature's geometry and properties
DELETE/v1/datasets/{datasetId}/features/{featureId}ownerDelete a feature. Returns 204

Pagination: when more results exist, the collection includes nextToken. Pass it back as a query parameter to get the next page.

Formats

Feature (request)

{
  "type": "Feature",
  "geometry": { "type": "Point", "coordinates": [-104.9903, 39.7392] },
  "properties": {
    "name": "Trailhead",           // required
    "category": "location",        // event | location | alert (others are stored but not styled)
    "description": "Parking for 10 cars"
    // any other properties are stored and returned as-is
  }
}
  • Coordinates are [longitude, latitude] (WGS 84), as GeoJSON requires.
  • Geometry types: Point, MultiPoint, LineString, MultiLineString, Polygon, MultiPolygon. The map currently draws points only.
  • Keep each feature under roughly 350 KB. Very detailed polygons aren't supported yet.

Feature (response)

GeoVivé adds id, datasetId, createdAt and updatedAt to properties, and sets the feature's top-level id. These are ignored if sent in a request.

Errors

Errors return JSON: { "message": "…" }.

StatusMeaning
400Invalid body, geometry or query parameter
401Missing, invalid or expired token
403Signed in, but not the dataset's owner
404Not found, or a private dataset you can't see
500Server error

Examples

Read a public dataset

curl https://api.geovive.link/v1/datasets
curl "https://api.geovive.link/v1/datasets/world-capitals/features?limit=50"

Create a dataset and add a pin

TOKEN="<access token>"

curl -X POST https://api.geovive.link/v1/datasets \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"Scouting spots","visibility":"private"}'

curl -X POST https://api.geovive.link/v1/datasets/<datasetId>/features \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"type":"Feature","geometry":{"type":"Point","coordinates":[-104.99,39.74]},
       "properties":{"name":"Trailhead","category":"location"}}'

JavaScript

const res = await fetch("https://api.geovive.link/v1/datasets/world-capitals/features");
const collection = await res.json();   // GeoJSON FeatureCollection
map.getSource("places").setData(collection);

Connected apps (coming soon)

GeoVivé is adding support for other sites to link a user's GeoVivé account with their own and work with that user's maps, with the user's consent. Planned:

  • Account linking via OAuth 2.0, with a GeoVivé consent screen and a Connected apps page where users can revoke access.
  • Open in GeoVivé links that send a user to a map for a specific item in your app, show your reference area, and return them when they're done.
  • App-scoped access: an app sees only maps created through it or shared with it.

Interested in integrating? Watch this page. Details will be published here as each part ships.
